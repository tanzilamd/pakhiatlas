# PakhiAtlas-এর লেখা কীভাবে সম্পাদনা করবেন

ছোটখাটো লেখা সংশোধনের জন্য কোনো সফটওয়্যার ইনস্টল বা ChatGPT-এর সাবস্ক্রিপশন লাগে না। নিজের GitHub অ্যাকাউন্ট দিয়ে [রিপোজিটরি](https://github.com/tanzilamd/pakhiatlas) খুলেই সম্পাদনা করতে পারবেন। প্রকাশিত সাইটের লেখাগুলো Markdown ফাইলে থাকে।

## ১. যে লেখাটি বদলাবেন, তার ফাইল খুঁজুন

সাইটের ঠিকানা দেখলেই সাধারণত ফাইলটি চেনা যায়। যেমন, `/pakhiatlas/bn/birds/cockatiel/` পাতার লেখা আছে `src/content/birds/bn/cockatiel.md` ফাইলে। একই লেখার ইংরেজি ফাইল `src/content/birds/en/cockatiel.md`।

| কী বদলাবেন | কোথায় পাবেন |
| --- | --- |
| বাংলায় পাখির প্রোফাইল | [src/content/birds/bn](../src/content/birds/bn) |
| ইংরেজিতে পাখির প্রোফাইল | [src/content/birds/en](../src/content/birds/en) |

| নাম, বৈজ্ঞানিক পরিচয়, ডাক ও আকারের শ্রেণি | [birds.json](../src/data/birds.json); বন্য পাখির জন্য [wildlife.json](../src/data/wildlife.json) |

প্রকাশিত প্রোফাইলের ছবি ও কিছু তথ্য আলাদা ডেটা ফাইল থেকে আসে। তাই শুধু Markdown বদলালে ছবির ক্যাপশন, তুলনার তথ্য বা ফুড চেকারের তথ্য বদলাবে না।

## ২. GitHub থেকেই ছোট একটি সংশোধন করুন

1. রিপোজিটরিতে `main` ব্রাঞ্চ বেছে সঠিক ফাইল খুলুন। যেমন [ককাটেলের বাংলা লেখা](../src/content/birds/bn/cockatiel.md)।
2. পেন্সিল চিহ্ন বা **Edit this file** চাপুন।
3. প্রয়োজনীয় লেখাটি বদলান। **Preview** থেকে শিরোনাম, অনুচ্ছেদ ও লিংক দেখে নিন।
4. **Commit changes…** চাপুন। কী বদলেছেন সংক্ষেপে লিখুন, যেমন `ককাটেলের খাবারের অনুচ্ছেদ সংশোধন`।
5. সরাসরি `main`-এ commit করার সুযোগ থাকলে সেটি বেছে সেভ করুন। নতুন ব্রাঞ্চে পরিবর্তন করলে pull request খুলে সেটি `main`-এ merge করতে হবে; শুধু ব্রাঞ্চে সেভ করলে মূল সাইট বদলাবে না।

শুধু বানান বা যতিচিহ্ন ঠিক করলে অন্য ভাষায় অকারণ পরিবর্তন দরকার নেই। তথ্যের অর্থ বদলালে বাংলা ও ইংরেজি—দুই সংস্করণেই একই তথ্য রাখুন।

দুই ভাষার ফাইল **এক commit-এ** বদলাতে চাইলে রিপোজিটরি খোলা অবস্থায় কিবোর্ডে `.` চাপুন, অথবা [GitHub web editor](https://github.dev/tanzilamd/pakhiatlas) খুলুন। দুই ফাইল সম্পাদনা করে **Source Control** থেকে পরিবর্তনগুলো stage করুন, বার্তা লিখে commit ও push করুন। সঠিক ব্রাঞ্চে আছেন কি না আগে দেখুন।

## ৩. ফাইলের কোন অংশ কী

প্রতিটি লেখার শুরুতে দুইটি `---` চিহ্নের মধ্যে তথ্যের একটি ব্লক আছে; একে frontmatter বলা হয়। আমাদের ফাইলগুলোতে এই অংশ JSON আকারে লেখা। তার নিচে মূল নিবন্ধ।

- `title`: পাতার শিরোনাম।
- `summary`: তালিকার কার্ড ও সার্চের জন্য সংক্ষিপ্ত পরিচিতি।
- `reviewedAt`: সত্যিকার সম্পাদনার তারিখ, `YYYY-MM-DD` আকারে। এটি পশুচিকিৎসকের পর্যালোচনার দাবি নয়।
- `sources`: [references.ts](../src/data/references.ts)-এর বিদ্যমান সূত্রের ID। নতুন তথ্যের জন্য উপযুক্ত সূত্রের নথিও হালনাগাদ করুন।
- `relatedGuides`: সংশ্লিষ্ট গাইডের slug-এর তালিকা; একই ভাষায় গাইডগুলো থাকতে হবে।
- গাইডের `topic`: নিচের অনুমোদিত বিষয়গুলোর একটি; বাংলা ও ইংরেজিতে একই মান রাখুন।

`slug`, `language`, `contentStatus` এবং ফাইলের নাম অকারণে বদলাবেন না। বর্তমানে `contentStatus`-এর অনুমোদিত মান `editorial-draft`; এটি সাইটে দেখানো কোনো লেবেল নয়। নিজের মতো `published` লিখলে validation ব্যর্থ হবে। JSON অংশে উদ্ধৃতি, কমা ও বন্ধনী ঠিক রাখতে হবে; শেষ item-এর পরে বাড়তি কমা দেবেন না।

গাইডের অনুমোদিত `topic`: `getting-started`, `feeding`, `everyday`, `behaviour`, `health`, `breeding`, `wildlife`।

মূল লেখায় সাধারণ Markdown ব্যবহার করুন:

```markdown
## অংশের শিরোনাম

এখানে অনুচ্ছেদ লিখুন। নতুন অনুচ্ছেদের আগে একটি ফাঁকা লাইন রাখুন।

- তালিকার প্রথম বিষয়
- তালিকার দ্বিতীয় বিষয়

**গুরুত্বপূর্ণ কথা**
```

কাজের লিংকের ধরন দেখতে পাশের বিদ্যমান লেখাটি অনুসরণ করুন। একই পরিচর্যার নির্দেশনা একাধিক নিবন্ধে কপি না করে মূল গাইডে লিখে সংশ্লিষ্ট প্রোফাইল থেকে লিংক দিন। প্রমাণ ছাড়া স্বাস্থ্যসংক্রান্ত সংখ্যা, চিকিৎসা বা বর্তমান বাজারদর বসাবেন না।

## ৪. পরিবর্তন সাইটে উঠেছে কি না দেখুন

[GitHub Actions](https://github.com/tanzilamd/pakhiatlas/actions) খুলে আপনার commit-এর **Deploy PakhiAtlas to GitHub Pages** workflow দেখুন। বিল্ড ও deploy—দুইটি সফল হলে আপডেট প্রকাশিত হয়। তারপর সংশ্লিষ্ট পাতাটি রিফ্রেশ করে বাংলা/ইংরেজি, লিংক ও মোবাইলে লেখা দেখে নিন।

লাল চিহ্ন দেখালে ব্যর্থ ধাপ খুলে error পড়ুন। সাধারণ কারণ: JSON-এ কমা/উদ্ধৃতির ভুল, ভুল source ID, ভুল topic, অনুবাদের ফাইল না থাকা বা ভাঙা লিংক। GitHub-এর লেখা সেভ হওয়া মানেই সাইটে প্রকাশ সফল হওয়া নয়; deploy ব্যর্থ হলে আগের সফল সংস্করণ সাধারণত চালু থাকে।

## ৫. নতুন পাখি, গাইড বা ছবি যোগ করবেন কীভাবে

**নতুন পাখি** যোগ করতে শুধু পুরোনো নিবন্ধ কপি করলেই হবে না। বাংলা/ইংরেজি লেখা, পরিচিতির canonical data, তুলনার তথ্য, সঠিক বাস্তব ছবি ও উৎসের নথি লাগবে। মিউটেশনের জন্য আলাদা প্রজাতির প্রোফাইল বানাবেন না। নতুন গাইডের দুই ভাষার ফাইল ও সঠিক `topic` থাকলে সেটি তালিকায় নিজে থেকেই আসে।

কম্পিউটারে Node.js 24 ও Git থাকলে রিপোজিটরি clone করে তার ফোল্ডারে এই কমান্ডগুলো চালাতে পারেন:

```bash
npm ci
npm run new:guide -- your-guide-slug
```

নতুন পাখির জন্য দ্বিতীয় কমান্ডের বদলে `npm run new:bird -- your-bird-slug` ব্যবহার করুন। তৈরি হওয়া দুই ফাইল পূরণ করুন, scaffold-এর নির্দেশনা সরান এবং প্রয়োজনীয় ডেটা/সূত্র যোগ করুন। অসম্পূর্ণ template প্রকাশের validation পাস করবে না।

তারপর পরীক্ষা করুন:

```bash
npm run check
npm run build
npm test
npm run preview
```

Preview কমান্ডে দেখানো ঠিকানা থেকে সাইট দেখুন। `build` করার পরে static search-ও পরীক্ষা করা যাবে। সব ঠিক থাকলে Git-এ commit করে `main`-এ push করুন। GitHub Actions স্বয়ংক্রিয়ভাবে প্রকাশ করবে।

ছবি যোগ করার কার্যকর কমান্ড, metadata ও ব্যবহারের শর্তের বিস্তারিত আছে [CONTENT_GUIDE.md](CONTENT_GUIDE.md)-তে। শুধু নতুন ছবি upload করলে সেটি নিজে থেকে প্রোফাইলে বসে না; photo record ও প্রজাতির মিল ঠিক করতে হয়। সিড মিক্সের ওজন বদলালে `originalTotalGrams`-ও মূল উপাদানগুলোর যোগফলের সমান রাখুন; ক্যালকুলেটরের কোড আলাদা করে বদলাতে হবে না।

## ৬. ভুল করে কিছু বদলে ফেললে

GitHub-এ ফাইলের **History** থেকে আগের সঠিক সংস্করণ দেখুন। প্রয়োজনীয় লেখা নিয়ে বর্তমান ফাইলে সংশোধন করে নতুন commit দিন। এতে পরিবর্তনের ইতিহাসও থাকে। কোনো AI সহকারীকে কাজ দিলে আগে [AGENTS.md](../AGENTS.md) ও [CONTENT_GUIDE.md](CONTENT_GUIDE.md) পড়তে বলুন—প্রকল্পের নিয়ম সেখানেই আছে।
